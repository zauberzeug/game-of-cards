# The committed OpenClaw bundle can drift from its TypeScript source with nothing to catch it

`openclaw-plugin/dist/index.js` is a **committed build artifact** — the file
the OpenClaw runtime actually loads — regenerated by hand with `npm run
build`. It is the only generated tree in this repo without a drift guard.

## Location

- `openclaw-plugin/package.json:6` — `"main": "./dist/index.js"`
- `openclaw-plugin/package.json:37` — the `build` script (`tsc
  --emitDeclarationOnly && esbuild index.ts --bundle …`)
- `openclaw-plugin/package.json:42-44` — `"openclaw": { "extensions":
  ["./dist/index.js"] }`
- `.pre-commit-config.yaml:4-9` — the only sync hook, scoped `files: ^goc/`
- `.github/workflows/release.yml:665-671` (npm leg) vs `:710-721` (ClawHub leg)
- `.game-of-cards/deck/openclaw-plugin-release-smoke-blockers-build-and-spawn-api/README.md:124`
  — where this was explicitly deferred

## What's broken

`dist/index.js` is what runs. `package.json` names it twice:

```json
  "main": "./dist/index.js",
...
  "openclaw": {
    "extensions": [
      "./dist/index.js"
    ],
```

It is produced from `index.ts` by a manual step:

```json
    "build": "tsc --emitDeclarationOnly && esbuild index.ts --bundle --platform=node --format=esm --outfile=dist/index.js --external:openclaw --external:openclaw/* --sourcemap",
```

Every *other* generated tree in this repo is tripwired, and `AGENTS.md` says so
explicitly:

> The auto-synced engine pair (`goc -> openclaw-plugin/goc`) is enforced by the
> same byte-for-byte tripwire as the Claude one. […] a drift guard keeps it
> honest even though it is not auto-staged: `scripts/port_skills_to_openclaw.py
> --check` re-ports into memory and fails on any difference […] The same
> comparison is enforced in CI by `tests/test_plugin_mirror_parity.py` […] so a
> template edit or sibling addition that is not followed by a re-port turns the
> build red instead of rotting silently.

`dist/` gets none of that. `AGENTS.md` mentions it only as something to collapse
in review — "the committed esbuild output (`openclaw-plugin/dist/**`) [is]
marked `linguist-generated=true`" — and `tests/test_gitattributes_generated_markers.py:46`
is the sole test that names the path, asserting only that the marker exists.

Worse, nothing even *fires* on an `index.ts`-only edit. The single relevant
pre-commit hook is scoped to the Python package:

```yaml
      - id: sync-plugin-assets
        name: sync plugin assets from goc/ to claude-plugin/
        entry: uv run python scripts/sync_plugin_assets.py
        language: system
        pass_filenames: false
        files: ^goc/
```

`openclaw-plugin/index.ts` does not match `^goc/`, so committing a TypeScript
change runs no hook at all.

This was foreseen and deferred. The closed card
[`openclaw-plugin-release-smoke-blockers-build-and-spawn-api`](../openclaw-plugin-release-smoke-blockers-build-and-spawn-api/),
which introduced the build pipeline, wrote:

> 3. `dist/` stays tracked in the repo (no `npm install` required to consume
> from a checkout — tester convenience). A future card can add a build-parity
> tripwire similar to `validate_plugin_mirror_parity` if dist/-vs-source drift
> becomes recurring.

No such card was ever filed. This is it.

## Empirical evidence

`reproduce.py` appends one line to `index.ts`, leaves `dist/` untouched, runs
every drift check the repo has, and restores the file:

```
artifact the OpenClaw runtime loads : openclaw-plugin/dist/index.js (115532 bytes)
source it is built from             : openclaw-plugin/index.ts

[mutate] appended `const GOC_DIST_DRIFT_PROBE_MARKER = 1;` to index.ts, left dist/ untouched
  index.ts contains marker : True
  dist/index.js has marker : False
  dist/index.js unchanged  : True

[guards] every drift check this repo runs, against the drifted tree:
  exit=0  scripts/sync_plugin_assets.py --check        PASS (misses the drift)
  exit=0  scripts/port_skills_to_openclaw.py --check   PASS (misses the drift)
  exit=0  goc validate                                 PASS (misses the drift)
  exit=0  python -m unittest discover -s tests         PASS (misses the drift)

restored openclaw-plugin/index.ts to its original bytes

DEFECT PRESENT: all 4 guards pass on a tree whose compiled
  dist/index.js no longer corresponds to index.ts. Nothing in pre-commit,
  CI, or the regression suite compares the two.
```

All 771 regression tests pass against the drifted tree (`Ran 771 tests in
41.630s` / `OK`). The current checkout is *not* drifted — `index.ts` and
`dist/index.js` last moved together in `ab49a62e` — so this is a latent trap,
not an active corruption.

## Why it matters

Two consumer paths read the committed bundle rather than a fresh build.

1. **Checkout-based installs.** `goc.md:232` documents this as the supported
   local-development path: "for local development the bundled `dist/index.js`
   is checked in so the plugin is loadable without a build step." A stale
   bundle means the plugin a tester loads is not the plugin whose source they
   are reading — the exact failure class that produced
   [`openclaw-plugin-goc-tool-fails-at-runtime-with-spawn-argv-error`](../openclaw-plugin-goc-tool-fails-at-runtime-with-spawn-argv-error/)
   and its siblings, where the loaded artifact and the reviewed source
   disagreed.

2. **The two publish legs are asymmetric.** `publish-npm` rebuilds before
   publishing:

   ```yaml
       - name: Build dist
         working-directory: openclaw-plugin
         run: npm run build

       - name: Publish to npm with provenance
         working-directory: openclaw-plugin
         run: npm publish --provenance --access public
   ```

   `publish-clawhub` has no build step at all — it hands the reusable workflow
   a repo ref and a subtree path:

   ```yaml
       uses: openclaw/clawhub/.github/workflows/package-publish.yml@v0.12.3
       with:
         source: ${{ github.repository }}
         ref: ${{ needs.build.outputs.clawhub_source_ref }}
         source_path: openclaw-plugin
   ```

   If that reusable workflow bundles the subtree as-committed, ClawHub and npm
   ship **different plugin code from the same tag**, while `goc.md:228` tells
   consumers "The same artifact is published to npm as `game-of-cards`."
   Whether ClawHub's publisher happens to run the `prepare` script (which would
   rebuild) is unverified from this repo — hence the EMPIRICAL DoD item. The
   defect stands either way; that answer only sets how far the blast radius
   reaches.

The porter precedent is the argument for fixing it rather than relying on
discipline: `openclaw-plugin/skills/` is also hand-regenerated and also not
auto-staged, and it still drifted twice
([`openclaw-plugin-ported-skills-drift-silently-from-templates`](../openclaw-plugin-ported-skills-drift-silently-from-templates/),
[`openclaw-card-schema-skill-mirror-stale-fails-ci`](../openclaw-card-schema-skill-mirror-stale-fails-ci/))
before the `--check` tripwire landed. `dist/` is the same shape with none of
the protection.

## Decision required

Which guard mechanism? The trade-off is *rigour* against *offline determinism*,
and one option is unavailable to the autonomous bot.

**Option A — rebuild-and-diff in CI.** A `ci.yml` step: `npm ci && npm run
build && git diff --exit-code -- dist/`.
*For:* catches every drift, including a `package.json`/`tsconfig.json` build-config
change that alters output without touching `index.ts`.
*Against:* needs Node + network in CI (~1 min added); requires the esbuild
bundle to be byte-reproducible across runner Node/esbuild patch versions — a
non-reproducible byte breaks the build on unrelated PRs. Also **the autonomous
bot's `GITHUB_TOKEN` cannot edit `.github/workflows/`**, so this option cannot
be implemented by a `pull-card` session — it needs a human commit. (This is the
same constraint that put the porter guard in a test rather than a `ci.yml`
step; see `AGENTS.md`.)

**Option B — offline source-hash sentinel.** Commit
`openclaw-plugin/dist/.build-source-sha256` holding a hash of the build inputs
(`index.ts` + the `build` script + `tsconfig.json`); a regression test in
`tests/` recomputes it and fails on mismatch, with the porter's placement
precedent.
*For:* pure Python, no Node, no network, runs in the existing suite, and lives
in `tests/` where the bot can write it.
*Against:* proves "you rebuilt after the last source change", not "dist is the
correct output of that source" — a hand-edited `dist/` with a refreshed
sentinel still passes.

**Option C — pre-commit staging guard.** A local hook scoped
`files: ^openclaw-plugin/(index\.ts|package\.json|tsconfig\.json)$` that fails
when those are staged without a `dist/` change.
*For:* cheapest; catches the actual human mistake at the moment it happens.
*Against:* pre-commit is bypassable (`--no-verify`) and is not run by the
`pull-card` GitHub Action (see
[`pull-card-workflow-skips-pre-commit-so-bot-commits-bypass-goc-validate`](../pull-card-workflow-skips-pre-commit-so-bot-commits-bypass-goc-validate/)),
so it is a nudge, not a gate.

B and C compose (sentinel as the gate, hook as the fast local nudge) and are
both bot-implementable; A is the only one that verifies the bytes, and it needs
a human to land the workflow edit.

## Fix

Deferred to the decision above. Whichever option is chosen, the contributor
rule belongs in `AGENTS.md` § "OpenClaw plugin payload — same engine, different
host shape", next to the existing "re-run
`python3 scripts/port_skills_to_openclaw.py`" instruction, which today lists
`openclaw-plugin/index.ts` among the files that are "NOT auto-synced" without
saying that editing it obliges a rebuild.
